# コリドール（Quoridor）実装指示書

以下の仕様に従い、モダンで堅牢なWeb版コリドールを実装せよ。

## 1. 開発要件・アーキテクチャ
- **技術スタック**: HTML5, CSS3, JavaScript (Vanilla JS, モジュール化)
- **レイヤー分離**: 
  - **ドメイン層 (domain.js)**: ゲームロジック、数学的判定、状態管理。
  - **ビュー層 (view.js, style.css)**: DOM操作、イベント、描画、アニメーション。
- **データ設計**: **イミュータブル（不変）**設計。ドメイン層のクラスは状態変更の際、常に新しいインスタンスを返すこと (`Object.freeze` を活用)。

## 2. ドメイン層の設計 (domain.js)
以下のクラスを定義し、それぞれにJSDocコメントを付与すること。

### ・Point / Wall / Player クラス
- 各要素の状態（座標、向き、ID、残りの壁数など）を保持する Value Object。

### ・Board クラス
- ボードの幾何学的な知識を担当。
- `isValidWallPlacement(wall)`: 壁の物理的な衝突（重なり・交差）を判定。
- `isWallBetween(p1, p2)`: 2マス間に壁が存在するか判定。
- `canReachGoal(player)`: 幅優先探索 (BFS) を用い、ゴールへの経路が最低1つ存在するか判定。

### ・Corridor クラス
- ゲーム全体の進行を管理するエントリーポイント。
- `isGameOver`, `isGameActive`: ゲーム状態を直感的に表すゲッター。
- `movePawn(newPos)`: 駒の特殊移動（跳び越し、跳び越し不可時の斜め移動）を実装。
- `placeWall(wall)`: 壁の設置判定とゴール封鎖チェックを行い、状態を更新。

## 3. ビュー層の設計 (view.js, style.css)
### ・GridSlot ヘルパークラス（view.js 内）
- 表示上の17x17グリッドの行・列番号から、それが「マス・水平壁・垂直壁・角」のどれかを判定。
- ドメイン座標（9x9）への変換および、壁による占有判定 (`isOccupiedBy`) を一括管理。

### ・QuoridorView クラス
- `render()`: 状態に応じた盤面更新。CSS変数を用いてボードサイズに応じたグリッドを動的に生成。
- **Undo機能**: history スタックに直前の Corridor インスタンスを保存し、一手戻る操作を可能にする。
- ユーザー入力を各スロット（Cell/Wall）にバインドし、ドメイン層のメソッドを呼び出す。

### ・スタイリング (style.css)
- **Premium Aesthetics**: ダークモード基調 (#0f172a), グラスモルフィズム, モダンフォント (Outfit 等) を使用。
- **レスポンス**: モバイルとPCで盤面サイズを最適化。
- **アニメーション**: 駒の移動可能位置へのパルスエフェクト、駒の移動や勝利時の遷移。

## 4. ゲームルール詳細
- **駒の移動**:
  1. 通常、上下左右に1マス移動可能。
  2. 相手の駒と隣接する場合、その上を跳び越せる。
  3. 跳び越した先が盤面外または壁である場合のみ、相手の駒から左右（斜め方向）に移動できる。
- **壁の設置**:
  1. 厚さ10px、長さ2マス分。
  2. お互いのゴール（端の行）へ到達する道を完全に遮断する壁は置けない。
- **勝利判定**:
  1. プレイヤー0は y=8 の行に到達、プレイヤー1は y=0 の行に到達すること。

## 5. 出力構成
1. index.html: UI構造（勝敗画面、Undoボタン含む）
2. style.css: モダンなデザイン定義
3. domain.js: イミュータブルなロジック全般
4. view.js: 表示とインタラクションの統合ロジック
